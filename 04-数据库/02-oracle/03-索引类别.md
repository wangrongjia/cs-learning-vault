## 1. FUNCTION-BASED NORMAL（基于函数的索引）

### 什么是函数索引？

对列应用函数后创建的索引，而不是直接对列值建索引。

### 示例：

```sql
-- 普通索引
CREATE INDEX idx_name ON employees(last_name);
-- 查询时必须: WHERE last_name = 'SMITH'

-- 函数索引
CREATE INDEX idx_upper_name ON employees(UPPER(last_name));
-- 现在可以优化: WHERE UPPER(last_name) = 'SMITH'

-- 常见的函数索引
CREATE INDEX idx_substr ON orders(SUBSTR(order_no, 1, 4));
CREATE INDEX idx_date ON sales(TO_CHAR(sale_date, 'YYYY-MM'));
CREATE INDEX idx_trim ON customers(TRIM(customer_name));
```

### 为什么容易出问题？

- 函数计算增加复杂度
- 统计信息收集困难
- 更容易触发优化器 bug（就像你遇到的 ORA-00600）
- 需要 `QUERY_REWRITE_ENABLED = TRUE` 和 `QUERY_REWRITE_INTEGRITY = TRUSTED`

## 2. B-Tree 索引（NORMAL - 最常见）

### 特点：

- **默认索引类型**
- 树状结构，适合高基数列（值分布广）
- 支持范围查询、排序

```sql
CREATE INDEX idx_employee_id ON employees(employee_id);
CREATE INDEX idx_composite ON orders(customer_id, order_date);  -- 组合索引
```

### 适用场景：

- 主键、外键
- 经常用于 WHERE、JOIN、ORDER BY 的列
- 值重复度低的列

### 查询示例：

```sql
-- 可以用到索引
WHERE employee_id = 100
WHERE employee_id BETWEEN 100 AND 200
WHERE employee_id > 100
ORDER BY employee_id
```

## 3. BITMAP 索引（位图索引）

### 特点：

- 使用位图（0和1）存储
- 适合**低基数列**（值重复度高，如性别、状态）
- **不适合频繁 UPDATE/INSERT/DELETE**

```sql
CREATE BITMAP INDEX idx_gender ON employees(gender);  -- 只有'M'/'F'两个值
CREATE BITMAP INDEX idx_status ON orders(status);     -- '待付款'/'已发货'/'已完成'
```

### 优势：

```sql
-- 位图索引对多条件查询效率极高
SELECT * FROM orders 
WHERE status = '已发货' 
  AND payment_method = '支付宝'
  AND region = '华东';
-- 可以直接做位运算：bitmap1 AND bitmap2 AND bitmap3
```

### 劣势：

- 更新时锁整个位图段（并发差）
- 只适合数据仓库/OLAP场景
- **OLTP系统禁用**

## 4. UNIQUE 索引

```sql
CREATE UNIQUE INDEX idx_email ON users(email);
-- 保证 email 值唯一
```

唯一性约束的索引，防止重复值。

---

## 5. REVERSE KEY 索引

### 特点：

反转键值后建索引，分散热点块

```sql
CREATE INDEX idx_seq_reverse ON orders(order_id) REVERSE;
-- order_id = 12345 存储为 54321
-- order_id = 12346 存储为 64321
```

### 适用场景：

- 序列号、自增ID等连续值
- 减少索引块争用
- **不支持范围查询**

---

## 6. 索引组织表（IOT - Index-Organized Table）

```sql
CREATE TABLE products (
    product_id NUMBER PRIMARY KEY,
    product_name VARCHAR2(100)
) ORGANIZATION INDEX;
```

表数据按主键顺序存储在索引结构中（没有独立的表段）。

---

## 7. 分区索引

### 本地分区索引（LOCAL）

```sql
CREATE INDEX idx_sales_local ON sales(sale_date) LOCAL;
-- 每个表分区有对应的索引分区
```

### 全局分区索引（GLOBAL）

```sql
CREATE INDEX idx_sales_global ON sales(customer_id)
GLOBAL PARTITION BY RANGE(customer_id) (...);
-- 索引分区独立于表分区
```

---

## 8. 域索引（DOMAIN）

用于特殊数据类型：

```sql
-- 全文检索索引
CREATE INDEX idx_text ON documents(content)
INDEXTYPE IS CTXSYS.CONTEXT;

-- 空间索引
CREATE INDEX idx_spatial ON locations(geo_location)
INDEXTYPE IS MDSYS.SPATIAL_INDEX;
```

---

## 9. 降序索引（DESCENDING）

```sql
CREATE INDEX idx_date_desc ON orders(order_date DESC);
-- 优化 ORDER BY order_date DESC 查询
```

## 索引类型对比表

|索引类型|适用场景|优点|缺点|
|---|---|---|---|
|**B-Tree (NORMAL)**|高基数列、通用场景|平衡、支持范围查询|空间占用较大|
|**BITMAP**|低基数列、数据仓库|多条件查询快、节省空间|更新锁粒度大|
|**FUNCTION-BASED**|对列应用函数查询|加速函数查询|维护成本高、易触发bug|
|**REVERSE KEY**|序列号、热点数据|分散竞争|不支持范围查询|
|**UNIQUE**|需要唯一性|保证数据完整性|插入时检查开销|

## 检查你表上的索引类型

```sql
SELECT 
    i.index_name,
    i.index_type,
    i.uniqueness,
    i.table_name,
    i.status,
    LISTAGG(ic.column_name, ', ') WITHIN GROUP (ORDER BY ic.column_position) as columns
FROM user_indexes i
LEFT JOIN user_ind_columns ic ON i.index_name = ic.index_name
WHERE i.table_name IN ('T_DOC_WAYBILL_HEADER', 'BMS_PRE_APPORTION')
GROUP BY i.index_name, i.index_type, i.uniqueness, i.table_name, i.status
ORDER BY i.table_name, i.index_name;
```

## 针对你的 ORA-00600 问题

**FUNCTION-BASED NORMAL 索引最容易触发优化器 bug**，建议：

### 1. 找出函数索引

```sql
SELECT index_name, table_name
FROM user_indexes
WHERE table_name = 'T_DOC_WAYBILL_HEADER'
  AND index_type = 'FUNCTION-BASED NORMAL';
```

### 2. 临时禁用函数索引测试

```sql
ALTER INDEX 索引名 UNUSABLE;
-- 然后重新执行你的查询

-- 如果问题解决，重建索引
ALTER INDEX 索引名 REBUILD;
```

### 3. 或者在查询中跳过该索引

```sql
SELECT /*+ NO_INDEX(e 索引名) */ ...
```
